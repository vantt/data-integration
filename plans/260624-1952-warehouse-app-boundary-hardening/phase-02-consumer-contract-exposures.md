## Architecture

### Exposure File Ownership Map

```
transformation/exposures.yml              ← Metabase only; auto-generated; DO NOT TOUCH
transformation/models/exposures_rill.yml  ← Rill dashboards; manually maintained; DO NOT EXTEND
transformation/models/exposures_consumers.yml  ← NEW: CRM, hug, Evidence, DetailView
```

Three files, three owners, zero overlap. If a new BI tool is added, it gets its own file.

### Consumer → Mart Dependency Map

```
CRM reverse-ETL (crm/sync/duckdb_reader.py)
  ├── dim_customers          (insight + base fetch — same mart, two projections)
  ├── mart_customer_tier
  ├── mart_customer_action_queue
  ├── mart_product_health
  ├── dim_products
  ├── fact_orders
  └── mart_deadstock_target_queue

hug identity resolver (crm/src/hug/identity_resolver_io.py)
  └── mart_hug_optin

Evidence (evidence/sources/datalake/)
  ├── fact_orders
  ├── dim_customers
  ├── dim_channels
  ├── fact_targets
  ├── fact_order_economics
  └── fact_order_returns

DetailView (baked in Docker image — partial)
  ├── fact_orders            (order header display)
  ├── fact_fulfillments      (Shipments tab)
  ├── dim_customers          (customer context)
  └── fact_order_economics   (COGS/margin recon panel)

Rill dashboards (already in exposures_rill.yml — reference, no duplication)
  ├── fact_orders + 5 dims   (orders_core)
  ├── fact_sales + 7 dims    (sales_items_core)
  └── fact_marketing_spend + 2 dims  (marketing_spend_core)
```

### Contract Doc Structure

```
docs/analytics-handbook/contracts/
  mart-consumer-contracts.md    ← NEW
```

Location chosen over `semantic/` because: this is consumer-side (who reads what, pinned columns), not producer-side (business definitions). Semantic layer = producer contracts. Contracts dir = consumer contracts. Clean separation.

## How to read this table

- **Pinned columns** = columns that a consumer references explicitly. Renaming or dropping these breaks the consumer. Untracked columns may exist in the mart and are transparent to that consumer.
- **Guard type** = how the consumer detects a missing column: `fail-loud` (raises + aborts), `query-error` (SQL bind error at runtime, visible but unhandled), or `none` (silent NULL / missing viz).
- **dbt exposure** = `dbt ls --select +exposure:<name>` returns this mart.
