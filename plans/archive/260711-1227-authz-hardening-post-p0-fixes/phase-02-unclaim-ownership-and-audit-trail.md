# Phase 2: Unclaim Ownership and Audit Trail

## Overview

2 route handlers ("Trả việc") — `handle_unclaim_customer` (`screen_worklist.py:527`, `PATCH /worklist/customers/{party_id}/unclaim`) and `handle_c360_unclaim_customer` (`screen_customer_360_panels.py:131`, `PATCH /customers/{party_id}/unclaim`) — both call the identical `TaskService.unclaim_customer_actions(party_id)` with zero ownership check today. Fix centralizes the ownership check + audit-note write INSIDE `TaskService.unclaim_customer_actions()` itself (single write path, matches this codebase's established "một đường ghi duy nhất" convention) rather than duplicating logic across 2 route handlers.

**Policy (discussed with user, decided)**: do NOT block the unclaim action outright — a rep can always drop a genuinely mismatched lead (wrong region, duplicate, etc.), blocking would deadlock that. Instead: (a) only the current assignee may unclaim (no admin override — `AppUser.role` exists but is "informational in v1, auth deferred" per `app_user.py:28-29`, no permission-check infrastructure exists to build a real override on; adding one now would be speculative scope), (b) unclaiming requires selecting a reason, written to an audit note (reuses the existing `crm_note` table + `NoteService.add_note()` — no new migration needed).

**CRITICAL correction after red-team review (2026-07-11) — the original design did not actually work.** All 4 independent reviewers found the same bug: the originally-specified guard (`if actor_id and not is_owner(...): return "forbidden"`) is **fail-open**, not fail-closed. Under this app's real deployment mode (LAN-trust, no CF Access — confirmed `current_user` is `None` in the default path, per `cf_access_middleware.py`), `_current_user_id(request)` returns `""` on essentially every request, so `actor_id` is falsy, the `if actor_id and ...` condition short-circuits to `False`, and the `"forbidden"` branch **never executes** — every unclaim silently succeeds regardless of who's asking. The fix below inverts the guard and adds an explicit unauthenticated-request rejection (matching the `handle_assign_me` 401 precedent this phase's own file list already cites). Also fixed in this revision: the audit-note write called the wrong port (raw `NoteRepository.add_note(note: Note)` vs. the `NoteService`-shaped kwargs call originally specified) which would have raised `TypeError` on every unclaim, silently swallowed by the mandated try/except — meaning the audit trail (this phase's other stated purpose) would never actually have been written. And: the `authz`/`notes` constructor changes break 8 existing `TaskService(...)` test call sites not originally listed — all 8 are now in scope.

## Requirements

- Only `assignee_user_id == current_user.user_id` may unclaim; mismatch → 403, no state change.
- Unclaiming requires a `reason` (non-empty, from a fixed short list) — missing/invalid reason → 422, no state change.
- A successful unclaim writes an audit note (`crm_note`, `note_type="unclaim_reason"`, `visibility="team"`) recording who unclaimed, when (implicit via `created_at`), and why.
- Both route handlers (worklist + C360) get identical behavior — logic lives once in `TaskService`, not duplicated.
- No new database migration (reuse `crm_note`).

## Architecture

`TaskService.unclaim_customer_actions()` currently returns `bool` (found/not-found). Change to return a 3-state string result (`"ok" | "not_found" | "forbidden"`) so both callers can map it to the right HTTP response without re-implementing the ownership check themselves.

**Uses `AuthorizationService` from Phase 1** for the ownership decision (`self._authz.is_owner(existing.assignee_user_id, actor_id)`) instead of an inline `==` comparison — this is the first of 2 consumers (Phase 3's IDOR fix is the second) that make Phase 1's centralization actually pay off immediately, not just theoretically. `TaskService` gains a constructor-injected `authz: AuthorizationService` alongside the new `notes: NoteService` (see correction below — NOT the raw repository).

**Fail-closed guard (corrected)**: `if not actor_id or not self._authz.is_owner(existing.assignee_user_id, actor_id): return "forbidden"`. Unauthenticated requests (`actor_id` empty) now hit the SAME `"forbidden"` branch as a genuine ownership mismatch — there is no separate "skip the check" path. The route handlers additionally reject unauthenticated requests before ever calling this method at all (belt-and-suspenders — see Implementation Steps 5/6), matching the `handle_assign_me` 401 precedent already cited in this file's own citations.

`TaskService` gains a constructor-injected `notes: NoteService` (**not** a raw `NoteRepository`, correcting the original design) — `NoteService.add_note(party_id, body, author_user_id=..., note_type=..., pinned=..., visibility=..., source_activity_id=...)` (`note_service.py:30-56`) is already the layer every other caller in this codebase goes through; wiring the raw `NoteRepository.add_note(note: Note)` instead (as originally specified) would require constructing a `Note` entity by hand AND bypass whatever validation `NoteService` does — no established precedent for calling the raw repo directly from application-layer code. Wired ONCE in `crm/src/composition.py` using the already-constructed `services["note"]` (`NoteService`, confirmed instantiated at `composition.py:323` per prior research — verify exact line at implementation time), not `sqlite_repos["note"]` (the raw repo).

## Implementation Steps

1. Add `VALID_UNCLAIM_REASONS` to `task.py` — **flat code-string list only** (e.g. `["wrong_region", "wrong_specialty", "duplicate_lead", "reassign_colleague", "other"]`), matching every other `VALID_*` constant's shape in this codebase exactly (confirmed via `activity.py`'s `VALID_OUTCOME_REASONS` — flat list, not tuples). VN display labels go in a separate small dict/lookup used only at the template/rendering layer (e.g. co-located in the same template that renders the `<select>`, or a small `_UNCLAIM_REASON_LABELS` dict near the constant if multiple templates need it) — do not put display strings in the domain constant. Keep the list small — lightweight audit signal, not a taxonomy project (YAGNI).
2. `TaskService.__init__`: add `notes: NoteService` and `authz: AuthorizationService` (from Phase 1) as **required** params, positioned correctly to avoid a `SyntaxError` — since Python disallows a required param after ones with defaults, and this constructor's existing `db=None, party_repo=None` already have defaults, add both new required params BEFORE `db`/`party_repo` in the signature (i.e. `__init__(self, task_repo, cache_repo, authz, notes, db=None, party_repo=None)`), OR make the whole signature keyword-only past the first 2 params (`__init__(self, task_repo, cache_repo, *, authz, notes, db=None, party_repo=None)`) — the keyword-only form is safer since it forces every call site (including the 8 test files below) to pass `authz`/`notes` by name, catching positional-arg mistakes immediately rather than silently shifting `db`/`party_repo` into the wrong slots. Prefer the keyword-only form.
3. `TaskService.unclaim_customer_actions(self, party_id: str, actor_id: Optional[str] = None, reason: Optional[str] = None) -> str`:
   - `existing = self._task_repo.get_customer_claim(party_id)`; if `None` → return `"not_found"`.
   - **`if not actor_id or not self._authz.is_owner(existing.assignee_user_id, actor_id): return "forbidden"`** — note the `not actor_id or` (fail-closed on empty/missing actor_id), NOT `actor_id and not ...` (the original, fail-open version red-team review caught). No `is not None` guard needed on `self._authz` — it's required, not optional (see step 2).
   - Proceed with existing cancel logic (`status = TASK_STATUS_CANCELLED`, `completed_at = utc_now()`, `self._task_repo.update(existing)`, commit).
   - If `reason` in `VALID_UNCLAIM_REASONS`: call `self._notes.add_note(party_id, body, author_user_id=actor_id, note_type="unclaim_reason", visibility="team")` — **`self._notes` is a `NoteService`, call its actual kwargs signature** (`note_service.py:30-56`), NOT a raw `NoteRepository.add_note(note: Note)` call (the original design's bug — verify at implementation time you're calling the right layer, this was flagged by 3 independent reviewers as broken). Body text e.g. `f"Trả việc — lý do: {reason_label}"` (look up `reason_label` from the small label dict added in step 1). Wrap in try/except-log (never let the audit-note write block the actual unclaim, matching this codebase's per-step failure isolation convention) — but now that the call shape is correct, this try/except is a genuine safety net, not a bug-masking device.
   - Return `"ok"`.

## Risk Assessment

- **Risk (was Critical, now fixed in this revision)**: the original guard was fail-open on empty `actor_id` — under this app's real LAN-trust deployment mode, this meant the ownership check never fired in practice. Fixed via `if not actor_id or not is_owner(...)` plus an explicit 401 at the route layer. Do not regress this during implementation — the failing test case (`actor_id=""` → forbidden) must exist and pass.
- **Risk (was Critical, now fixed)**: the audit-note write originally called the wrong port (raw `NoteRepository` with `NoteService`-shaped kwargs) — would have raised `TypeError`, silently swallowed by the try/except, meaning no audit note was ever actually written. Fixed by wiring `NoteService` (not the raw repo) and calling its real signature. Verify with an actual DB query in the test, not just an HTTP-status assertion — this is exactly the kind of bug an HTTP-only test would miss.
- **Risk (was Critical, now fixed)**: `TaskService.__init__`'s new required params broke 8 test call sites not originally listed — now explicitly enumerated in Related Code Files and Implementation Steps.
- **Risk**: the `authz`/`notes` instance in `composition.py` — if Phase 1 already instantiates `AuthorizationService()` there, this phase must reuse that SAME instance, not create a second one (Phase 1's revised design commits to exactly one shared instance) — verify at implementation time which phase's edit lands first and reuse accordingly.
- **Rollback**: revert `TaskService.__init__`/`unclaim_customer_actions` to prior signature, revert `composition.py` wiring, revert 2 route handlers + 2 templates + the `TaskClaimWriter` Protocol + 8 test files — more files than originally scoped, but each change is independently revertable.
